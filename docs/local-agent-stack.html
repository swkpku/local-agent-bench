§03

Size Your Machine

Step 1the memory budget

Everything above rents space in your memory. The model's weights have to fit in RAM (or GPU VRAM) alongside its context — so your memory is the size of model you can run. Find your tier; it decides everything downstream.

Your RAM / VRAMModel class · 4-bitGood picksWhat to expect
8 GB3–4B · ~2–3 GBQwen3 4B · Llama 3.2 3B · Gemma 3 4BSnappy chat and simple single-tool calls. Real agent loops are a stretch.
16 GBreference7–9B · ~5–6 GBQwen3 8B · Gemma 3 12B (tight)The sweet spot — reliable single / few-tool agents at ~10–15 tok/s on Apple Silicon.
24–32 GB14–32B · ~9–20 GBQwen3 14B / 32B · Gemma 3 27BMulti-step loops get genuinely reliable, with headroom for long context.
64 GB+30–70B · MoEQwen3 30B-A3B · Llama 3.3 70BApproaching frontier quality for many tasks — still fully local.
the budget

RAM = ceiling

On Apple Silicon, CPU + GPU share one unified memory pool, so a 4-bit 9B fits in 16 GB with room for context. On a PC, your GPU VRAM is the real budget; CPU-only works but runs slowly.

how it fits

Quantization

4-bit (Q4_K_M) shrinks a 9B from ~18 GB to ~5–6 GB for a small quality cost. It's the default sweet spot — start here; only climb to Q5/Q6 if you have spare RAM.

the speed cap

Bandwidth

Tokens/sec is bound by memory bandwidth, not raw compute — a bigger model moves more bytes per token, so it runs slower. Leave ~2–4 GB free for the OS.

§04

Install a Runtime

Step 2serve the model over HTTP

The runtime loads the weights and exposes them as an OpenAI-compatible HTTP API — so any agent can talk to it, and you can swap models without touching anything above. Pick one; they all speak the same protocol.

recommended · easieststart here

Ollama

One binary, every OS, a built-in model library. ollama pull & ollama run and you're done. Serves an OpenAI API at :11434/v1.

GUI · no terminal

LM Studio

A desktop app: search a model, click download, flip on Local Server. Runs both GGUF and MLX. Best if you'd rather not touch a shell. Serves at :1234/v1.

most control

llama.cpp

The lean engine under the hood of most others. llama-server gives you GBNF grammars, KV-cache tuning and --jinja tool parsing. What this repo standardizes on. Serves at :8080/v1.

install + servebash
# ── Ollama (recommended) ──────────────────────────────
$ brew install ollama                              # macOS · or download the app
$ curl -fsSL https://ollama.com/install.sh | sh   # Linux
$ ollama serve                                     # now live at localhost:11434

# ── llama.cpp (more control) ──────────────────────────
$ brew install llama.cpp                           # or build from source
$ llama-server -hf bartowski/Qwen3-8B-GGUF:Q4_K_M --jinja --ctx-size 16384 --port 8080

Windows: Ollama and LM Studio both ship native installers. On Apple Silicon, MLX (mlx_lm.server) decodes ~20–30% faster if you want it. Scaling past a laptop? vLLM does GPU-first batched serving. The key point either way: everything above only sees http://localhost:<port>/v1, so you can switch runtimes later for free.

§05

Pick & Pull a Model

Step 3where capability lives

The open weights themselves, in GGUF, quantized to your tier from Step 1. One thing matters most for agents: tool-call reliability is a property of the model, not the harness above it. These families are the safe bets.

best small tool-callerdefault

Qwen3

0.6B → 235B incl. MoE. Tool template baked in, strong structured-output fidelity — the most reliable small open tool-caller. qwen3:8b is the 16 GB default.

strong all-rounder

Gemma 3

1B / 4B / 12B / 27B dense. Native function calling, system prompts, long context, vision on the bigger ones. gemma3:12b on 16 GB (tight), gemma3:4b on 8 GB.

specialists

Coder · Llama

qwen2.5-coder (1.5–32B) is the local coding pick; llama3.1:8b / llama3.3:70b are solid general tool-callers when you have the RAM.

pull a modelbash
# Ollama — picks a sane 4-bit quant for you
$ ollama pull qwen3:8b      # 16 GB · the default agent model
$ ollama pull qwen3:4b      # 8 GB
$ ollama pull qwen3:14b     # 32 GB   (use the newest tag your library lists)

# llama.cpp — pull a specific GGUF quant straight from Hugging Face
$ llama-server -hf bartowski/Qwen3-8B-GGUF:Q4_K_M --jinja
Tool-calling reliability scales hard with model size
7B ≈ 71%
14B+ multi-step
32B+ ≈ 80%
9B class
<7B · falls off a cliffBFCL-style accuracy →near GPT-4o

The single most useful fact on this page: a 7–9B is the floor for usable agents — reliable for single / few-tool steps, marginal for long autonomous loops. Below ~7B no harness can save it, so don't fight a too-small model. Bigger RAM tier → bigger model → more reliable loops.

Worth knowing
  • Quant: start at Q4_K_M. Drop to IQ4_XS if it's tight; rise to Q5_K_M / Q6 only with spare RAM.
  • MoE (e.g. qwen3:30b-a3b) gives big-model quality at small-model speed — if you have 32 GB+ to hold all the experts.
  • Reasoning models (DeepSeek-R1 distills) can fight agent harnesses — keep "thinking" off for tool use, or expect leaked traces.
§06

Verify It Works

Step 4the shared contract

Before wiring an agent, confirm two things over the API the runtime exposes: the model answers, and — the one that actually matters for agents — it emits a valid tool call. That contract (/v1/chat/completions with tools) is exactly why any harness can talk to any runtime.

smoke-test the endpointbash
# 1 · does it answer?
$ curl localhost:11434/v1/chat/completions -H 'Content-Type: application/json' -d '{
    "model": "qwen3:8b",
    "messages": [{"role":"user","content":"reply with one word: ready"}]
  }'

# 2 · does it emit a tool_call?  ← the real agent-readiness test
$ curl localhost:11434/v1/chat/completions -H 'Content-Type: application/json' -d '{
    "model": "qwen3:8b",
    "messages": [{"role":"user","content":"What is 19*23? Use the tool."}],
    "tools": [{"type":"function","function":{
      "name":"calc","description":"evaluate math",
      "parameters":{"type":"object","properties":{"expr":{"type":"string"}}}}}]
  }'
# ✓ look for "tool_calls" in the response — not a number in the text
the baseline

Chat + tools

/v1/chat/completions with tools / tool_calls — the OpenAI-compatible lingua franca every layer here speaks.

the safety net

Structured output

JSON-schema responses and GBNF grammars force generation into a valid shape at decode time. If a small model emits messy JSON, this is the fix.

tools & data

MCP

Model Context Protocol: a standard socket for tools and data. Write a tool once, plug it into any MCP-aware agent (next step).

No tool_calls in the response? Make sure tool parsing is on (--jinja on llama.cpp; on by default in Ollama for tool-capable models) and that your model is one of the tool-callers from Step 3 — not every GGUF supports it.

The Agent Loop

harness · what the loop is

A plain chat call answers once. A harness wraps it in a loop, lets the model act through tools, and feeds the world's response back — until it decides it's done.

§08

Run an Agent

Step 5point a harness at your endpoint

The payoff. A harness wraps your model in the plan→act→observe loop and connects it to real tools. Install one, point it at your localhost endpoint, and go. Its biggest design choice — and what to match to a small model — is how the loop acts.

— the action mechanism · two paradigms
▲ better for small / open models

Code-as-Action

model writes & runs Python
  • Plays to a model's strongest skill: writing code
  • Is data analytics — load, transform, plot
  • One code block replaces many tool calls
  • smolagents · Qwen-Agent · Open Interpreter
  • Needs a sandbox to run the code
VS
structured · auditable

JSON Tool-Calling

model emits structured calls
  • Clean, typed, easy to validate & audit
  • "Consistently weaker" on open models
  • Small models emit malformed JSON — the #1 failure
  • Aider · Goose · Pydantic AI
  • Force validity with GBNF grammars

Not strictly either/or — a common hybrid is JSON tool-calling where one tool is run_python, giving you code-as-action as a tool.

Three recipes that work today against the endpoint from Step 2 — pick by what you want to do:

install + run an agentbash
# ── CODING · Aider (git-native pair programmer) ───────
$ pip install aider-chat
$ export OLLAMA_API_BASE=http://127.0.0.1:11434
$ aider --model ollama_chat/qwen3:8b

# ── DATA / CODE-AS-ACTION · smolagents (Python) ───────
$ pip install smolagents litellm
$ python - <<'PY'
from smolagents import CodeAgent, LiteLLMModel
m = LiteLLMModel("ollama_chat/qwen3:8b", api_base="http://127.0.0.1:11434")
CodeAgent(tools=[], model=m, additional_authorized_imports=["pandas","matplotlib"]).run(
    "Load sales.csv and chart revenue by month")
PY

# ── GENERAL · Open WebUI (ChatGPT-style UI + tools) ───
$ pip install open-webui && open-webui serve     # → localhost:8080, finds Ollama

All three only need the OpenAI-compatible URL from Step 2 — swap qwen3:8b for whatever you pulled, or point api_base at :8080 (llama.cpp) / :1234 (LM Studio).

Block's agent with thousands of MCP extensions. Add SQL / web / file tools without writing code. Strong general pick.

ChatGPT-style local UI over Ollama, with functions, RAG and MCP. Friendliest for non-coders.

Type-safe tools, schema validation + self-correction retries. Best for structured pipelines.

Instructor json

Lightest layer to coerce output into validated JSON. A component, not a loop.

A small model's comfort zone
  • Great: data analytics (it's just code), focused file edits, structured extraction, RAG over your own docs.
  • Workable, supervised: multi-file coding in 5–8 step bursts with per-step approval (Cline / Aider).
  • Hard locally: long autonomous loops, and computer-use (driving a browser/OS from screenshots) need ≥32B. Research needs a real search tool, or the model will confidently make things up.
§10

Make It Reliable

levers that span the layers

No single layer makes a small model reliable — these levers cut across several at once.

✓
Constrain the outputGBNF grammars / JSON-schema decoding force valid tool calls at generation time. (runtime + protocol)
✓
Match the tool templateEnable the model's tool parser in the runtime (e.g. --jinja for Hermes-style Qwen). (runtime + model)
✓
Keep the prompt smallA small model has little context to spare — minimal system prompt, few tools. (harness)
✓
Repair & retryParse-fix malformed calls; feed tracebacks back so the model self-corrects. (harness)
✓
Keep data out of the promptPass schema + a few sample rows; let code crunch the full dataset. (task + harness)
✓
Bump ctx, cap horizon16–32k context for real loops; keep tasks to 5–8 supervised steps. (hardware + task)
